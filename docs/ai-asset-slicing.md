# AI-assisted asset slicing

The desktop app can find reusable buttons, icons, panels and screens in imported artwork using SVG geometry and an Ollama vision model. Open a document, then choose **Layers panel menu → Slice Artwork with AI…** (command `ui.sliceWithAI`).

1. Run Ollama and install a vision model yourself, for example `ollama pull qwen2.5vl:3b`. The app does not download models. The default endpoint is `http://localhost:11434/api/chat`; `curl` must be available.
2. Choose the model and name language. Enable **Selection Only** to detect elements in the selected artwork. Otherwise the preview covers the document artwork bounds.
3. **Ignore sheet background** is enabled by default. It excludes a bottommost solid rectangular backdrop matching an artboard and enclosing at least two other objects. It only changes the temporary preview/export copy; disable it to retain the backdrop. Clipped or styled containers are never searched for backdrops.
4. Click **Play**. VectorCraft separates spatial islands of sibling artwork using painted bounds. Overlapping parts stay together, while clipped, masked, styled or translucent containers remain whole. Small detached captions stay with a dominant control. Tiny bounds overlaps (up to 2% of the smaller part) are tolerated so touching shadows do not join adjacent assets. The model names each region from a separate white-backed preview (at most 512 pixels on its longest side); it never supplies coordinates. Each preview is sent to the configured server. A remote endpoint receives that preview too. Inference runs off the UI thread. The preview appears before naming finishes, and ready regions arrive one at a time with progress. **Pause** preserves ready regions and lets the current request finish; no next request starts until **Play**. The current request can take up to 120 seconds.
5. Review the numbered boxes over the preview. Edit names and document-coordinate X/Y/width/height fields; uncheck unwanted regions. Names are validated; bounds come from the vector artwork; suggestions are not a guarantee that an element is correctly detected.
6. On pause, ready regions can already be exported or created as slices while the current request finishes. Choose a destination folder and **SVG** or **PNG**, then **Export Regions**, or click **Create Slices** to add the checked regions as ordinary editable document slices in one undo step. Export and slice creation are separate actions. After successful creation or export, processed rows are unchecked automatically; names, edits and exclusions remain. New ready rows are checked. Recheck an old row explicitly to process it again. Stable region-number prefixes allow successive exports into the same folder, including equal names. Existing files are never overwritten. Closing the dialog pauses the job and keeps its checkpoint in the current app session, including the in-flight response; reopen the dialog and press Play to continue. **Start Over** clears proposals and starts afresh without undoing slices or deleting exported files. Checkpoints are not restored after restarting the app.

For detected regions, direct **Export Regions** and the model preview isolate the source group or all members of its spatial component with their original ancestors, clipping and appearance. This prevents neighbouring objects from entering a crop even when a compound path has conservative bounds; the rectangle may still include transparent margins. Manually supplied regions without source IDs use ordinary rectangular cropping. **Create Slices** always creates ordinary rectangular document slices, without detaching or isolating source objects.

SVG exports keep vectors, groups, clipping and effects through the existing SVG writer. Artwork outside each crop is pruned where it can be removed without breaking group appearance; paths crossing a crop stay whole and the SVG viewport clips them. PNG exports use transparent backgrounds at the chosen scale. For manual regions without source IDs, both formats crop everything inside the rectangle, so overlapping art and other painted backgrounds remain. This is region extraction, not semantic background removal or automatic reparenting of paths. Complex masks retain their original hierarchy.

Export names have a numeric prefix and a sanitized element name. Existing files are never replaced. A failed write rolls back files created by that batch. Detection also bounds traversal to 32 levels and 4096 siblings per container; narrow the selection for more complex sheets. Batches are limited to 64 regions, 16 million raster pixels, and 64 MiB of encoded output. Changing the document invalidates proposals; selection-only proposals also reject a changed selection. Settings remain locked until Start Over. Partial Create Slices updates the checkpoint revision and preserves the object selection so Play continues the original scope and skips all previously named regions. The original artwork is never moved or renamed.

AI detection currently requires the desktop app. The engine commands remain available through CLI/MCP/control:

- `slice.aiSnapshot {selectionOnly?, ignoreBackground?}` returns document `uid`, `revision`, preview `rect`, spatial `regions` (including `sourceIds` for every component member) and `selectionIds`.
- `slice.applyAI {uid, revision, selectionOnly?, selectionIds?, regions}` adds named slices. The optional `preserveSelection:true` keeps the object selection (used by the player); the default selects the new slices. Regions contain `name`, `x`, `y`, `width`, `height` in document points. With selection scope, supply the snapshot's `selectionIds`.
- `slice.exportAI {uid, revision, selectionOnly?, selectionIds?, regions, ignoreBackground?, format?, scale?, folder?}` exports checked regions. An optional `candidateIndex` (0–63) supplies a stable export-number prefix across partial batches. Preserve the snapshot rows’ optional `sourceIds` to isolate all detected component members; omit them for rectangular crops of all artwork. Omitting `folder` returns base64 files. It does not change the document or the undo history.

Tests cover model-name validation, spatial separation and intact clipped groups, review/cancel/apply, document and selection guards, atomic creation and undo/redo, vector crop contents, transparent PNG dimensions, safe names and refusal to overwrite. An ignored live-model test accepts `VECTORCRAFT_SLICING_SVG` to name the first four candidates of a local multi-element user-owned fixture without committing it.
